RACER on ROS 2. Frontier detection, decentralised task allocation, tour planning and B-spline trajectories for a quadrotor swarm, migrated from ROS 1 to ROS 2 Humble.

Overview

This project is a ROS 2 Humble port of RACER by Boyu Zhou, Hao Xu and Shaojie Shen (SYSU-STAR/RACER). The exploration algorithm, planners and simulator are their work; this repository contributes the migration to ROS 2, the containerised build and the tooling around it. Please cite the original paper.

RACER is a hierarchical planning framework for fast collaborative exploration of unknown 3-D environments with a decentralised quadrotor swarm. Each UAV detects frontiers in its own map, the team divides the unexplored space through decentralised task allocation, each UAV plans a coverage tour, and a B-spline optimiser produces smooth, collision-free trajectories that are replanned in real time.

The original system targets ROS 1 Noetic, which reached end of life in 2025. This port moves the complete stack to ROS 2 Humble on Ubuntu 22.04 so it can be used with current ROS 2 robots, simulators and tooling, and packages it in Docker for a one-command build.

Porting Work

25ROS packages migrated
164C++ source and header files
64rclcpp node sources
6Python launch files
  • Build system. Every package moved from catkin to ament_cmake, with package.xml format 3 and rewritten CMakeLists.txt dependencies.
  • Source migration. Scripted, repeatable conversion of headers, message types, publishers, subscribers, timers, parameters and logging from roscpp to rclcpp across all C++ sources, followed by manual fixes for node lifecycles and executors.
  • Messages. Custom quadrotor, trajectory and exploration messages regenerated with rosidl.
  • Launch. XML launch files rewritten as Python launch descriptions for single-drone and swarm exploration, the light simulator and RViz.
  • Containerised build. A Dockerfile for Ubuntu 22.04 and ROS 2 Humble with PCL, Eigen and NLopt, so the stack builds and runs without touching the host.
  • Tooling. A ROS 2 visualisation node that plots the obstacle cloud, explored map and drone trajectory for quick checks without RViz.

Default simulation: a 50 m × 50 m × 3.5 m map with 150 cylinders and 150 circular obstacles.

Quick Start

docker build -t multi_decent_expl .
./run_docker.sh

Or build from source on Ubuntu 22.04 with ROS 2 Humble:

colcon build --symlink-install
source install/setup.bash
ros2 launch exploration_manager sim_single_drone.launch.py

Exploration starts automatically after about 20 seconds. In RViz, set the fixed frame to world and add /map_generator/global_cloud, /sdf_map/occupancy_all_1, /planning_vis/trajectory_1 and /planning_vis/frontier_1.
